# Аккаунты Spell and Iron Rift

Собственная система аккаунтов проекта. Она работает **поверх** лицензии Minecraft и ничего в ней не отключает.

| Что | Чем подтверждается |
|---|---|
| Право играть в Minecraft (покупка игры) | вход через Microsoft в лаунчере (официальная схема запуска) |
| Личность в проекте: ник, UUID аккаунта, роль, бан | аккаунт Spell and Iron Rift (ник + пароль) |
| Что этот игрок на сервере — именно владелец аккаунта | привязка аккаунта к профилю Minecraft через сессионный сервер Mojang |

## Как это устроено

```
Лаунчер ──регистрация / вход (ник+пароль)──▶ Rift Control /api/account   (Argon2id, сессии, роли, баны)
   │
   ├─ вход через Microsoft ─▶ профиль Minecraft (UUID, токен)
   │
   └─ привязка: /link/challenge → serverId
                 лаунчер → sessionserver.mojang.com/session/minecraft/join (токен Minecraft уходит только в Mojang)
                 Rift Control → sessionserver.mojang.com/session/minecraft/hasJoined → UUID подтверждён

Игровой сервер (online-mode=true) ─ мод Guard ─▶ Rift Control /api/server/players/<UUID>  (ключ сервера)
   └─ пускает только привязанные активные аккаунты, выдаёт права по роли, показывает ник проекта
```

## Что выполнено из требований

- **Регистрация в лаунчере** по нику (3–16: латиница, цифры, `_`, как в Minecraft) и паролю: не меньше 8 символов, буквы и цифры, без ника. Ники уникальны без учёта регистра, служебные имена (admin, server…) запрещены.
- **Постоянный UUID** у каждого аккаунта (UUID v4). Он не меняется при смене пароля, роли или профиля Minecraft.
- **Пароли:** Argon2id, параметры OWASP (19 МиБ, 2 прохода). Пароль нельзя прочитать даже администратору. При неверном нике ответ приходит за то же время, что при неверном пароле.
- **Собственный сервер авторизации:** модуль `backend/src/accounts.ts`, маршруты `/api/account/*`.
- **Сессия между запусками:** токен на 30 дней. При каждом запуске лаунчер обменивает его на новый (ротация). Хранится зашифрованным ключами ОС (DPAPI / Keychain / libsecret), как и вход Microsoft.
- **Восстановление пароля через администратора:** в Rift Control → «Аккаунты игроков» → «Сбросить пароль». Игрок получает временный пароль и обязан сменить его при входе. Все его сессии завершаются.
- **Защита от подмены ника и UUID:**
  - профиль Minecraft привязывается только после проверки Mojang (`join`/`hasJoined`), и один профиль Minecraft можно привязать только к одному аккаунту;
  - мод Guard работает только при `online-mode=true`, где UUID при входе проверяет сам Mojang;
  - ник в игре берётся из аккаунта проекта, а не из клиента.
- **Роли Player / Moderator / Admin:** назначаются в Rift Control. На сервере Guard выдаёт уровни оператора: модератор — 3, администратор — 4 (настраивается). Операторов, назначенных владельцем вручную, Guard не трогает.
- **Блокировка и удаление:** бан с причиной сразу завершает сессии лаунчера, и Guard в течение минуты выкидывает игрока с сервера. Удаление освобождает ник.
- **Защита от перебора:** 8 неудачных входов → пауза 15 минут (по IP и по нику). Не больше 5 регистраций с одного IP в час.
- **Интерфейс:** экран входа и регистрации в стиле лаунчера с подсказками по паролю, смена пароля, карточка аккаунта в «Профиле», раздел в Rift Control.

## Настройка

1. **Rift Control:** запустите как обычно. Ключ игрового сервера создаётся сам: `data/keys/server-api.key`. Его видно владельцу в разделе «Аккаунты игроков».
2. **Лаунчер:** `launcher/config/app.json → apiBase` — адрес Rift Control (https).
3. **Игровой сервер:**
   - положите `spellironrift-guard-*.jar` в `mods/`;
   - в `server.properties` должно стоять `online-mode=true`;
   - после первого запуска заполните `config/spellironrift-guard.json`:
     ```json
     { "apiBase": "https://rift.example.org", "serverKey": "<ключ из Rift Control>", "moderatorOpLevel": 3, "adminOpLevel": 4, "useCacheWhenOffline": true, "recheckSeconds": 60 }
     ```
   - перезапустите сервер. В логе появится `Spell and Iron Rift Guard is on`.

Если Rift Control временно недоступен, Guard пускает игроков, которые уже успешно проходили проверку (кеш). Новых игроков без проверки он не пустит.

## Тестовый режим

Вход по нику без Microsoft остаётся только для «Моего сервера» на этом ПК или в локальной сети: для проверки модов. Guard в таком режиме не включается, потому что при `online-mode=false` UUID ничем не подтверждён.
